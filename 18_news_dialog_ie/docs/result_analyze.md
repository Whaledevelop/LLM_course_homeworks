# Анализ результатов

## Проверенный smoke-прогон

В текущем окружении проверен только CPU-профиль на пяти уникальных синтетических примерах:

```powershell
python scripts/run_demo.py --sample-size 5 --gold-size 5 --batch-sizes 1 2 4 --profiles rules --allow-synthetic --rebuild-cache
```

Он подтверждает работу CLI, batching, cache, RAM, оценки качества и CSV-артефактов. Актуальные точные значения находятся в `data/benchmark_results.csv`. Эти цифры не являются итоговым сравнением моделей из-за синтетического источника и малого размера выборки.

Автоматическая проверка:

```text
11 passed
```

## Что ещё требует фактического запуска

В среде разработки отсутствуют PyTorch, CUDA и локальные веса 7B-моделей. Поэтому результаты Mistral/OpenChat, FP16/INT8 и VRAM не выдуманы и не внесены в отчёт. Для завершения экспериментальной части необходимо выполнить итоговую команду из README на NVIDIA GPU после ручной разметки 200 реальных диалогов.

## Как анализировать итоговую таблицу

- Сравнивать FP16 и INT8 одной модели при одинаковом batch size по throughput, latency, VRAM, valid JSON rate и F1.
- Сравнивать Mistral и OpenChat на одном precision mode и одной gold-выборке.
- Для качества использовать micro F1 как общую метрику, macro F1 и per-class CSV — для поиска слабых классов.
- Проверить `extraction_errors.csv`, особенно неоднозначные `PERSON/ORG`, несколько событий, даты без года, отсутствующий источник и привязку нескольких impacts.
- Максимальный batch выбирать среди успешных прогонов, учитывая не только docs/sec, но и p95 latency и запас VRAM.

## Ожидаемые trade-offs

Rules остаётся самым быстрым и прозрачным baseline, но ограничен словарями и шаблонами. spaCy расширяет покрытие стандартных NER-классов, но не решает доменные `IMPACT` и отношения. FP16 LLM требует больше VRAM; INT8 должен уменьшить память и может повысить доступный batch size ценой возможного снижения качества или скорости на конкретном GPU. Эти выводы следует подтвердить фактическими значениями, а не ожидаемыми оценками.
