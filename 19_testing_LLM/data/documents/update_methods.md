# Методы обновления в Unity

## Update

`Update` вызывается у включённого `MonoBehaviour` один раз за отрисовываемый кадр. Частота вызова зависит от частоты кадров и поэтому не является постоянной. В `Update` обычно обрабатывают ввод, изменяют нефизическое состояние и выполняют логику, которая должна проверяться каждый кадр.

Перемещение с постоянной скоростью нельзя вычислять как фиксированное смещение за вызов `Update`: при разной частоте кадров итоговая скорость будет различаться. Для пересчёта величины «в секунду» в величину «за текущий кадр» применяется `Time.deltaTime`. Например, расстояние за кадр равно произведению скорости на `Time.deltaTime`.

## Time.deltaTime

`Time.deltaTime` содержит время в секундах между текущим и предыдущим кадрами. Это значение меняется вместе с длительностью кадра. Если скорость равна 5 единицам в секунду, выражение `5f * Time.deltaTime` задаёт смещение, соответствующее времени конкретного кадра.

Внутри `FixedUpdate` обращение к `Time.deltaTime` возвращает фиксированный временной шаг. Сам шаг настраивается свойством `Time.fixedDeltaTime`; его значение по умолчанию в новом проекте обычно равно 0,02 секунды, то есть 50 шагам в секунду игрового времени.

## FixedUpdate

`FixedUpdate` работает по расписанию фиксированного шага, а не строго один раз на визуальный кадр. Перед кадром Unity может вызвать его ноль раз, один раз или несколько раз: это зависит от накопившегося игрового времени и длительности кадра.

Расчёт физики Unity выполняется после `FixedUpdate`. Поэтому силы и другие управляющие воздействия на `Rigidbody`, связанные с физическим шагом, задают в `FixedUpdate`. Например, `Rigidbody.AddForce` обычно вызывают из этого метода. Это позволяет синхронизировать изменение физического тела с частотой симуляции.

Фиксированный шаг не означает, что `FixedUpdate` гарантированно вызывается через одинаковые интервалы реального времени. При задержке кадра несколько фиксированных шагов могут быть обработаны подряд.

## LateUpdate

`LateUpdate` вызывается один раз за кадр после завершения всех вызовов `Update`. Типичный проверяемый порядок внутри кадра: сначала `Update`, затем `LateUpdate`. Это позволяет сначала изменить состояние объекта, а затем выполнить зависимую от нового состояния логику. Например, камера может обновить позицию в `LateUpdate` после перемещения цели в `Update`.

## Разделение задач

`Update` и `LateUpdate` относятся к циклу визуальных кадров. `FixedUpdate` относится к фиксированным шагам и связан с физической симуляцией. `Time.deltaTime` используют для масштабирования изменений по прошедшему времени, но само наличие `deltaTime` не превращает покадровый код в физический шаг.
