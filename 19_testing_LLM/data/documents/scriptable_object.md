# ScriptableObject в Unity

## Что такое ScriptableObject

`ScriptableObject` — базовый класс Unity для объектов данных, существующих независимо от `GameObject`. В отличие от `MonoBehaviour`, экземпляр `ScriptableObject` нельзя присоединить к объекту сцены как компонент. У него нет собственного `Transform`, а сообщения покадрового поведения вроде `Update` не являются его обычным назначением.

Класс данных наследуют от `ScriptableObject`, а сериализуемые поля объявляют по правилам сериализации Unity. Ссылку на созданный объект можно хранить в сериализуемом поле компонента, другого `ScriptableObject` или другого поддерживаемого Unity объекта.

## Создание asset

Атрибут `CreateAssetMenu` добавляет команду создания пользовательского типа в меню `Assets/Create`. После выполнения команды Unity создаёт файл asset в проекте. Такой файл имеет собственный GUID в метаданных проекта, поэтому другие assets и объекты сцены могут хранить на него ссылки.

Экземпляр также можно создать из кода методом `ScriptableObject.CreateInstance<T>()`. Сам по себе этот вызов создаёт объект в памяти, но не записывает его как файл проекта. Для сохранения asset из редакторского кода применяют API пространства имён `UnityEditor`, например `AssetDatabase.CreateAsset`. API `UnityEditor` не включают в сборку проигрывателя.

## Хранение и совместное использование данных

Asset на основе `ScriptableObject` хранит сериализованные данные в проекте. Один и тот же asset можно назначить нескольким компонентам. В этом случае компоненты ссылаются на один объект данных, а не получают независимую копию всех его полей.

Такой способ позволяет вынести общие конфигурации из экземпляров объектов сцены. Например, отдельный asset может содержать числовые характеристики типа предмета, а несколько компонентов могут ссылаться на эту конфигурацию.

Изменение asset в редакторе сохраняется как изменение проектного файла. Изменения полей `ScriptableObject` во время работы собранного приложения не превращают asset проекта в постоянное пользовательское хранилище. Для сохранений игры требуется отдельный механизм записи данных.

## Отличие от MonoBehaviour

`MonoBehaviour` существует как компонент конкретного `GameObject` и участвует в жизненном цикле сцены. `ScriptableObject` не требует объекта сцены и может использоваться несколькими сценами и компонентами через ссылки на asset.

Оба типа наследуются от `UnityEngine.Object` и поддерживают сериализацию Unity, но имеют разные роли. `MonoBehaviour` связывает код с объектом сцены, а `ScriptableObject` представляет самостоятельный контейнер сериализуемых данных.

Методы `OnEnable` и `OnDisable` могут вызываться и у `ScriptableObject`, однако наличие этих сообщений не делает его компонентом. Уничтожение экземпляра в памяти выполняют через `Object.Destroy` во время работы приложения, а удаление asset-файла в редакторе является отдельной операцией.
