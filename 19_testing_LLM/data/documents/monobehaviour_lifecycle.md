# Жизненный цикл MonoBehaviour

## Назначение сообщений жизненного цикла

`MonoBehaviour` — базовый класс Unity для сценариев, присоединяемых к `GameObject`. Unity вызывает его специальные методы как сообщения движка. Разработчик не обязан вызывать `Awake`, `Start` или `Update` вручную. Эти методы могут быть объявлены без модификатора `public`.

## Awake

`Awake` вызывается при загрузке экземпляра скрипта. Для объекта сцены это происходит при загрузке сцены, а для созданного во время выполнения объекта — после его создания. Метод вызывается один раз за время существования экземпляра `MonoBehaviour`.

`Awake` выполняется даже у компонента, у которого свойство `enabled` равно `false`, если содержащий его `GameObject` активен при загрузке. Если сам `GameObject` неактивен, вызов откладывается до его активации. `Awake` подходит для внутренней инициализации экземпляра. Unity не гарантирует порядок `Awake` между разными объектами, если он не настроен через Script Execution Order.

## OnEnable и Start

`OnEnable` вызывается каждый раз, когда компонент становится активным и включённым. Это возможно после `Awake`, при включении компонента через `enabled = true` или при активации его `GameObject`. При повторных циклах выключения и включения `OnEnable` вызывается повторно, тогда как `Awake` повторно не вызывается.

`Start` вызывается перед первым обновлением кадра, только если экземпляр включён. Он выполняется не более одного раза. Поэтому повторное включение компонента не приводит к повторному вызову `Start`. Для объектов, присутствующих в сцене при её запуске, вызовы `Awake` и `OnEnable` завершаются до вызова `Start` у этих объектов.

## OnDisable и OnDestroy

`OnDisable` вызывается, когда активный включённый компонент перестаёт быть включённым: например, при `enabled = false`, деактивации `GameObject` или уничтожении объекта. При последующей активации ему соответствует новый вызов `OnEnable`.

`OnDestroy` вызывается перед уничтожением объекта или компонента. При уничтожении активного включённого компонента сначала происходит `OnDisable`, затем `OnDestroy`. В отличие от `OnDisable`, `OnDestroy` является завершающим событием для данного экземпляра: после него экземпляр не включается снова.

## Типичная последовательность

Для активного включённого компонента при загрузке сцены базовая последовательность выглядит так: `Awake` → `OnEnable` → `Start` → обновления кадров. При обычном уничтожении после работы следуют `OnDisable` → `OnDestroy`.

Эта схема описывает порядок сообщений одного экземпляра. Порядок одноимённых методов у разных объектов не следует считать определённым без явной настройки порядка выполнения скриптов.
