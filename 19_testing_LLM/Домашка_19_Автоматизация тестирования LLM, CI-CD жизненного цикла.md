Создание пайплайна CI/CD с автотестами и проверкой на галлюцинации

Цель:

В этом ДЗ вы протестируете LLM с помощью Ragas и интегрируете её в CI/CD-пайплайн.

  

Описание/Пошаговая инструкция выполнения домашнего задания:

**Пошаговая инструкция:**  
  

1. Подготовка проекта.  
      
    

- Создайте простое LLM‑приложение (например, RAG, QA‑бот или суммаризация).
- Добавьте requirements.txt/pyproject.toml с зависимостями (ragas, datasets, transformers, pytest).  
      
    

2. Золотые примеры (goldens).  
      
    

- Подготовьте 10–20 входов с эталонными ожиданиями (правильные ответы, ключевые факты).
- Сохраните в формате JSON/CSV (tests/goldens.json).  
      
    

3. Тестирование с Ragas.  
      
    

Настройте пайплайн оценки с Ragas:  
  

- Faithfulness (проверка на галлюцинации);
- Answer Relevance;
- Context Recall.  
      
    

Запустите тесты на ваших goldens и сохраните результаты.  
  

4. Автотесты.  
      
    

- Оберните Ragas‑оценки в unit/integration тесты (например, через pytest).
- Добавьте простые проверки: минимальные пороги по метрикам (например, Faithfulness ≥ 0.7).  
      
    

5. CI/CD (опционально).  
      
    

- Настройте GitHub Actions или GitLab CI, которые запускают Ragas‑тесты.
- Добавьте quality gates: пайплайн должен «падать», если метрики ниже порога.  
      
    

Если CI/CD настроить не удалось — опишите, какие шаги вы бы добавили (jobs, артефакты, quality gates).  
  

6. Отчёт.  
      
    

- Сохраните результаты работы Ragas в формате JSON/HTML.
- В README.md / прямо в ноутбук укажите: какие метрики использовались, какие пороговые значения выбраны, как их использовать в CI/CD.

**Формат сдачи:**  
  

1. Репозиторий (GitHub/GitLab) с кодом, тестами и CI/CD-конфигом
2. Скриншоты результатов (метрики Ragas, успешные/неуспешные тесты).
3. Если CI/CD реализован — скриншоты успешного/проваленного прогона.  
      
    

Если у вас возникнут вопросы, вы можете задать их в чате проверки домашнего задания или в группе в Telegram.

  

Критерии оценки:

Статус "Принято", при наличии:

1. Корректное использование Ragas — запуск тестов, сохранение результатов.
2. Качество тестов — есть goldens, проверка на галлюцинации, метрики с порогами.
3. CI/CD интеграция или описание — либо рабочий пайплайн, либо чёткое описание шагов.
4. Документация — README / отчёт с инструкцией и интерпретацией результатов.

  

Компетенции:

- Разрабатывать, дообучать и оптимизировать LLM, расширяя их функциональность через Fine-tuning, вызов внешних функций, локальный запуск и извлечение информации из текста
    - - использовать fact-checking
    - - писать тесты под различные сценарии
